# Requirements Archive v2.1: Terminal Sessions

**Status:** ✅ SHIPPED 2026-06-16
**Milestone:** v2.1 Terminal Sessions
**Outcomes:** 14 v1 requirements shipped, 4 v1 requirements reclassified to v2 deferred (PERS-01..PERS-04), 7 v2 requirements remain deferred

## v1 Requirements (Final)

Requirements for v2.1 Terminal Sessions milestone. Each maps to roadmap phases.

### Session Management

- [x] **SESS-01**: User can create a new terminal session with a default name — Phase 21
- [x] **SESS-02**: User can see a list of all terminal sessions in a tab bar — Phase 23
- [x] **SESS-03**: User can switch between terminal sessions by clicking tabs — Phase 23
- [x] **SESS-04**: User can rename a terminal session — Phase 21
- [x] **SESS-05**: User can close a terminal session — Phase 21 (confirmation gate added in 25-03)
- [x] **SESS-06**: User can reorder terminal session tabs via drag-and-drop — Phase 23

### Session Execution

- [x] **EXEC-01**: User can execute a saved command in the active terminal session — Phase 24
- [x] **EXEC-02**: Command variables are resolved (CEL defaults, env, prompts) before sending to session — Phase 24
- [x] **EXEC-03**: Command working directory is applied (per-command → global default → session cwd) — Phase 24 + Phase 25 (global default inheritance)
- [x] **EXEC-04**: Long-running processes (servers, watchers, tail) continue running when user switches sessions — Phase 21
- [x] **EXEC-05**: Command output streams to the active session's terminal in real-time — Phase 24
- [x] **EXEC-06**: User can send Ctrl+C to interrupt a running command in the active session — Phase 24

### Session UI

- [x] **UI-01**: Terminal tabs show session name and status indicator (idle/running/busy) — Phase 23
- [x] **UI-02**: Right-click tab shows context menu (rename, close, duplicate) — Phase 23
- [x] **UI-03**: Keyboard shortcuts: New tab (Ctrl+T), Close tab (Ctrl+W), Next tab (Ctrl+Tab), Prev tab (Ctrl+Shift+Tab) — Phase 23
- [x] **UI-04**: Terminal output preserves scrollback per session (5000 lines) — Phase 23
- [x] **UI-05**: Session theme matches app theme (CSS variables) — Phase 23
- [x] **UI-06**: Clear terminal button clears only the active session — Phase 23

## v1 Requirements Reclassified to v2 (Deferred)

These four requirements were originally v1 for the v2.1 milestone but were reclassified to v2 deferred during Phase 25 D-02/D-03 (in-memory scope chosen for v2.1). The shipped v2.1 is **in-memory only** for sessions.

- [ ] **PERS-01**: Terminal sessions persist across app restarts (name, working dir, shell) — **Deferred to v2**
- [ ] **PERS-02**: On startup, previous sessions are restored and available in tab bar — **Deferred to v2**
- [ ] **PERS-03**: Session working directory is restored (per-command → global default → OS home fallback) — **Deferred to v2**
- [ ] **PERS-04**: Active session is remembered and auto-selected on restart — **Deferred to v2**

## v2 Requirements (Deferred)

Deferred to future release. Tracked but not in current roadmap.

### Advanced Session Features

- **SESS-07**: User can duplicate a session (clone working dir, env, history)
- **SESS-08**: User can split terminal pane horizontally/vertically (tmux-style)
- **SESS-09**: User can broadcast input to multiple sessions simultaneously

### Session Sharing

- **SESS-10**: User can export session layout as workspace file
- **SESS-11**: User can share session output via link (read-only)

### Enhanced Persistence

- **PERS-05**: Session scrollback history persisted across restarts
- **PERS-06**: Shell command history persisted per session

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real-time collaboration / shared sessions | Multi-user, not personal tool |
| Session recording/replay | Future enhancement |
| Custom per-session shell configuration | Settings scope creep |
| Full tmux-style pane management | UI complexity, not requested |
| Background session notifications | Complex, low priority |

## Notes on Changed Requirements

**PERS-01..PERS-04 reclassification (Phase 25 D-02/D-03):**

- **Original v1 scope:** Database persistence for terminal sessions across app restarts
- **Reclassified to v2 during Phase 25:** In-memory v2.1 ships; persistence deferred to v2
- **Rationale (D-02):** Deliver the multi-session UX now; persistence is a separable concern
- **Rationale (D-03):** Phase 22 has 0 plans; rather than build a persistence layer that the rest of the milestone doesn't need, defer to v2 where it can be designed as a first-class feature
- **Impact:** v2.1 sessions do not survive app restart. Phase 22 is empty in the milestone archive.
