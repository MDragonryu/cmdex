# Phase 23 — UI Design Contract

> Visual and interaction contract for the frontend tabbed terminal. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Source pre-population: CONTEXT.md decisions D-01 through D-04, Agent's Discretion section, existing style.css tokens, existing TabBar/Terminal components.

---

## Focal Points

| Priority | Element | Rationale |
|----------|---------|-----------|
| Primary | The active terminal viewport | Largest visual region in the pane; high-contrast light text (`var(--foreground)`) on dark background (`var(--background)`) dominates the user's attention |
| Secondary | The active tab's accent underline (`var(--tab-active-indicator)`) | The 2px bottom border in accent blue draws the eye to session identity within the tab bar |

## Spacing Scale

Declared values (must be multiples of 4). Extracted from `src/style.css` density variables and existing component patterns.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tab close button radius, tag chip gaps |
| sm | 8px | Compact element spacing, density padding/gap defaults |
| md | 16px | Default element spacing, section padding (comfortable density) |
| lg | 24px | Layout gaps |
| xl | 32px | Major section breaks |
| 2xl | 48px | Page-level spacing |
| 3xl | 64px | Page-level spacing (reserved) |

### Exceptions

Values below are locked by existing global CSS tokens in `frontend/src/style.css` and cannot be changed without breaking the command editor tab bar, header layout, dirty-dot indicators, and global scrollbar. These are justified, not violations.

| Value | Element | Justification |
|-------|---------|---------------|
| **35px** | Tab bar height (`var(--tab-bar-height)`) | Global layout token, shared with command editor `.tab-bar` and `--header-height`. Changing 35→36 would misalign the header, editor tabs, and terminal tab bar across the entire app (3+ components). |
| **18px** | Tab close button (width × height, `.tab-close`) | Existing `.tab-close` in `style.css` line 609–610. Changing 18→16 or 18→20 would alter close button sizing on command editor tabs as well as terminal tabs. |
| **6px** | Status dot diameter (`.tab-dirty-dot`) + scrollbar width (`::-webkit-scrollbar`) | Shared `.tab-dirty-dot` sizing (line 628–629); scrollbar width is a system-wide override (line 512). Both are small visual elements where 4px is too small and 8px is oversized. |
| **12px** | Comfortable density padding (`padding-lg`) + tab bar item inner padding | Intermediate step between compact (8px) and default (16px). Required by the existing `[data-density="spacious"]` / `[data-density="compact"]` density system in `style.css`. Not part of the standard scale; used only where the density system demands it. |
| **2px** | Tab close button border radius, dirty-dot margin-right | Micro-spacing for small visual details. Not part of the standard scale. |

## Color

All colors use CSS custom properties. No hardcoded hex values in component code. The terminal tab bar inherits the app theme via `var()` references.

### Default Theme (VSCode Dark+)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` (#1e1e1e) | Terminal viewport background, tab bar area behind active tab |
| Secondary (30%) | `var(--tab-bar-bg)` (#2d2d2d) | Tab bar background, inactive tab backgrounds |
| Accent (10%) | `var(--tab-active-indicator)` (#007acc) | Active tab bottom border, "+" button hover, context menu item focus |
| Tab active bg | `var(--tab-active-bg)` (#1e1e1e) | Active tab fill — visually merges with terminal below |
| Tab inactive bg | `var(--tab-inactive-bg)` (#2d2d2d) | Inactive tab fill |
| Tab hover bg | `color-mix(in srgb, var(--tab-active-bg) 60%, var(--tab-inactive-bg))` | Tab hover state |
| Status dot — running | `var(--success)` (#4ec9b0) | Green dot when shell process is alive |
| Status dot — stopped | `var(--muted-foreground)` (#858585) | Gray dot when shell process has exited |
| Status dot — busy | `var(--primary)` (#007acc) | Blue dot while PTY is streaming output |
| Close button hover | `var(--muted)` (#3c3c3c) → `var(--foreground)` (#d4d4d4) | Close button background/color transition |
| Context menu bg | `var(--popover)` (#2d2d2d) | Dropped-down menu background |
| Context menu border | `var(--border)` (rgba 255,255,255,0.1) | Menu border |
| Context menu hover | `var(--accent)` (#2a2d2e) | Menu item hover state |
| Destructive | `var(--destructive)` (#f44747) | "Close" text in context menu when session has running process |

Accent (`--tab-active-indicator` / `var(--primary)`) reserved for: **active tab bottom border only, and "+" new tab button hover state**. The accent is NOT used for: tab titles, close buttons, status dots, context menu items.

### All Themes

The tab bar supports all 8 themes (VSCode Dark+, VSCode Light+, Monokai, Tokyo Night, One Dark Pro, Classic, Catppuccin Mocha, Dracula) through the existing CSS variable system. Each theme has its own `--tab-bar-bg`, `--tab-active-bg`, `--tab-inactive-bg`, `--tab-active-indicator`, `--primary`, `--success`, `--muted-foreground` values. No theme-specific overrides needed in component code.

## Interaction Contract

### Tab Switching

| Trigger | Behavior |
|---------|----------|
| Left-click tab | Calls `SetActiveSession(tabId)`, updates frontend `activeSessionId`, hides previous terminal pane, shows new one |
| Ctrl+Tab | Select next tab (index + 1, wrap to 0 at end) |
| Ctrl+Shift+Tab | Select previous tab (index - 1, wrap to last at start) |
| Scroll on tab bar | Horizontal scroll (already built into `.tab-bar`'s `overflow-x: auto`) |

### Tab Creation

| Trigger | Behavior |
|---------|----------|
| Click "+" button | Calls `CreateSession()`, backend returns new session ID. New tab appears, auto-selected. Terminal component mounts for new session. |
| Ctrl+T | Same as clicking "+" button |

### Tab Closing

| Trigger | Behavior |
|---------|----------|
| Click close (×) button | Calls `CloseSession(tabId)`, removes tab from list, unmounts terminal. If this was the active session and others exist, auto-select nearest tab. |
| Ctrl+W | Closes active tab. If only 1 tab exists, no-op (last tab not closeable). |
| Right-click → Close Session | Same as click close button. Disabled (grayed out) when only 1 tab exists. |

### Context Menu (Right Click)

| Trigger | Behavior |
|---------|----------|
| Right-click tab (anywhere on tab item) | Opens ContextMenu at cursor position with two items: "Rename Session" and "Close Session" |
| Click "Rename Session" | Opens Rename dialog (or inline edit — implementer's choice per Agent's Discretion in CONTEXT.md). Calls `RenameSession(tabId, newName)` on confirm. |
| Click "Close Session" | Same as close button. Disabled for last tab. |

### Status Indicators

| State | Dot Color | Condition |
|-------|-----------|-----------|
| Running | `var(--success)` (#4ec9b0) | `SessionInfo.running === true` |
| Stopped | `var(--muted-foreground)` (#858585) | `SessionInfo.running === false` |
| Busy (output streaming) | `var(--primary)` (#007acc) with subtle pulse | `pty-output:{sessionId}` event received in last 300ms |

Status dots update via event listeners on `pty-exit:{sessionId}` (running→stopped) and `pty-output:{sessionId}` (running→busy→running after 300ms idle timeout).

### Tab Reorder (Drag and Drop)

| Trigger | Behavior |
|---------|----------|
| Drag tab to new position | Visual-only reorder — frontend state updates tab order. No backend persistence (Phase 22 skipped). Leverages existing TabBar's drag-and-drop mechanism from the command editor tabs. |

### Keyboard Shortcuts Summary

| Shortcut | Action | Scope |
|----------|--------|-------|
| Ctrl+T | New session | Global (works even when focus is in terminal) |
| Ctrl+W | Close active session | Global (no-op on last tab) |
| Ctrl+Tab | Next session | Global |
| Ctrl+Shift+Tab | Previous session | Global |

_Note: Keyboard shortcuts follow the existing `useKeyboardShortcuts` pattern — modifiers fire even when focus is in the xterm.js textarea. Bare keys only fire when focus is NOT in an editable element._

### Scrollback

Each `TerminalComponent` instance preserves its own xterm.js buffer. When a terminal pane is hidden (`display: none`), xterm.js retains its scrollback buffer in memory. Re-showing the pane restores the full scrollback. Scrollback limit: **5000 lines per session** (existing `Terminal.tsx` configuration, `scrollback: 5000`).

### Clear Button

The existing terminal clear button calls `Clear(sessionId)` with the active session ID. When multiple sessions exist, the clear button clears ONLY the active session's terminal — other sessions' output is preserved. No changes needed to the existing clear button logic.

## State Management

| State | Storage | Purpose |
|-------|---------|---------|
| `sessions: SessionInfo[]` | React `useState` in App.tsx | Full list of active sessions from `ListSessions()` |
| `activeSessionId: string` | React `useState` in App.tsx | Currently selected session — drives which TerminalComponent is visible |
| `sessionStatus: Record<string, 'running' \| 'stopped' \| 'busy'>` | React `useState` or `useRef` | Per-session status for dots, updated via events |
| Tab order (for drag-drop) | React `useState` (derived from sessions array) | Visual order of tabs in bar |
| Terminal output per session | xterm.js buffer (in-memory, per TerminalComponent instance) | Each TerminalComponent ref holds its own xterm Termainal instance |

**Mounting strategy:** Mount all `TerminalComponent` instances up front (one per session in `sessions` array). Show only the active one via CSS (`display: none` for inactive). This preserves scrollback without remounting on tab switch. Use `key={sessionId}` on each TerminalComponent wrapper to ensure React doesn't recycle instances.

## Edge Cases

| Scenario | Expected Behavior |
|----------|-------------------|
| Only 1 session exists | Close button hidden, Ctrl+W no-op, Context Menu Close item disabled |
| Maximum sessions (e.g., 20+) | Tab bar scrolls horizontally (existing `.tab-bar` `overflow-x: auto`), scrollbar hidden via `scrollbar-width: none` |
| Session creation fails | Toast error message, no tab added, active session unchanged |
| Rename to empty string | Prevent — dialog confirm button disabled when input is empty/whitespace-only. Revert to previous name. |
| Rename to existing name | Allowed — session names are not unique. No validation needed. |
| Terminal component ref not ready | Guard with null check before dispatching Write/Clear/Resize |
| Rapid Ctrl+T presses | Debounce not needed — backend handles session creation, frontend appends to list on success callback |
| Drag tab off bar (no target) | Tab snaps back to original position (existing behavior from command editor TabBar) |
| Multiple sessions, close active non-last | Auto-select nearest tab (next if exists, else previous). Active session changes before close completes. |
