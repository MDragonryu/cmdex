<objective>
Refactor the keyboard shortcut handlers in App.tsx to support focus-dependent dispatch: when keyboard focus is in the terminal pane area, Ctrl+T/W/Tab/Shift+Tab operate on terminal sessions; otherwise they preserve existing command tab behavior. This resolves the shortcut conflict identified in RESEARCH.md Pitfall 1.

Purpose: Ctrl+T, Ctrl+W, Ctrl+Tab, and Ctrl+Shift+Tab are ALREADY bound to command tab operations in App.tsx (lines 1154, 1162-1164, 1169, 1176). The user expects these same shortcuts to control terminal tabs when interacting with the terminal pane. Without focus-dependent dispatch, pressing Ctrl+T would open a command tab AND create a terminal session simultaneously — broken behavior.

Output: Modified App.tsx with focus-aware keyboard shortcut handlers that dispatch to terminal or command tab operations based on `document.activeElement` location.
</objective>

- Modifier combos (ctrl/meta/alt) fire EVEN when focus is in an INPUT/TEXTAREA/contentEditable.

    **Step 1: Add focus detection helper (add at the top of the useKeyboardShortcuts call block, before the handler definitions around line 1128)**

    Add a helper function at the top of the component body (NOT inside useKeyboardShortcuts, but accessible to the handlers via closure). Place it after the existing callbacks from Plan 02 (after `handleReorderTerminalTabs`):

    ```typescript
    const isFocusInTerminalPane = useCallback((): boolean => {
        const el = document.activeElement;
        if (!el) return false;
        // Check if the active element is inside .terminal-pane or is the xterm.js hidden textarea
        return !!(
            (el as HTMLElement).closest?.('.terminal-pane') ||
            (el as HTMLElement).closest?.('.xterm-helper-textarea')
        );
    }, []);
    ```

    This helper returns true when the user's keyboard focus is in the terminal area. The `useCallback` with empty deps keeps the reference stable — the function body always reads `document.activeElement` at call time (not stale).
