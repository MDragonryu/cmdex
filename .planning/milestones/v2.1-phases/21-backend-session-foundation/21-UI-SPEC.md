## Color

Preserved from existing design system. Default theme: VS Code Dark+.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1e1e1e` (`--background`) | Background, surfaces, terminal background |
| Secondary (30%) | `#2d2d2d` (`--secondary`) | Cards, sidebar, nav, tab bar |

## Phase-Specific: Frontend Event Wiring Changes

Phase 21 introduces **no new UI components** but requires **event name wiring updates** to match the backend's switch from global events to namespaced per-session events.

### Changed Files

| File | Change | Rationale |
|------|--------|-----------|
| `frontend/src/wails/events.ts` | Remove `ptyOutput`, `ptyExit`, `ptyCleared` fields from `eventNames` object and `initEventNames()` assignment | Backend removes `EventNames.PtyOutput/PtyExit/PtyCleared` per D-04 (clean break). Frontend constants must match. |
| `frontend/src/components/Terminal.tsx` | Replace `eventNames.ptyOutput` → dynamic `"pty-output:" + sessionId`, same for `ptyExit`/`ptyCleared` | Backend emits `pty-output:{sessionId}` per D-04. Component must construct subscription key from `sessionId` prop. |

### Existing Patterns Preserved

- Event subscription pattern: `Events.On(eventName, handler)` → returns cleanup function — unchanged
- `Write(sessionId, data)` signature (with sessionId parameter) — binding regenerated by `wails3 generate build-assets`
- `Resize(sessionId, cols, rows)`, `Clear(sessionId)`, `Start()` signatures — binding regenerated
- `TerminalHandle` interface (`clear`, `getSelection`, `getLastOutput`) — preserved
- xterm.js configuration (font, theme, scrollback, addons) — unchanged
- `sonner` toast error display pattern — unchanged

### No Layout/Visual Impact

- No CSS changes
- No new DOM elements
- No layout shifts
- Screen reader behavior unchanged (xterm.js manages its own accessibility)
- Keyboard navigation unchanged (terminal input via `term.onData` unchanged)
