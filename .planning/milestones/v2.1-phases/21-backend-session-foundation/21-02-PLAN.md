    **1. `(s *TerminalService) startSessionLocked(ss *sessionState, cols, rows int) error`:**
    - The `ss` session's own `ss.mu` MUST be held by caller. `TerminalService.mu` is NOT held.
    - Guard: if `ss.starting`, return nil (prevent double-start).
    - Set `ss.starting = true`.
    - Clamp cols/rows: `if cols < 10 { cols = 80 }`, `if rows < 3 { rows = 24 }`.
    - Call `stopSessionLocked(ss)` (defined below) to clean up any previous PTY.
    - Snapshot old PTY/cmd to local vars, clear `ss.ptmx = nil; ss.cmd = nil; ss.running = false; ss.intentionalStop = false`.
    - Call `detectShell()` to get shellPath, shellFlag.
    - **CRITICAL unlock-before-blocking:** Call `ss.mu.Unlock()` before any blocking ops.
    - Close old PTY, kill old process group, wait on `ss.readerWg`.
    - Call `ptyStart(shellPath, shellFlag, rows, cols)` — same signature as terminal_unix.go.
    - Re-acquire: `ss.mu.Lock()`.
    - Set `ss.starting = false`. Return error if ptyStart failed.
    - Populate: `ss.shellPath`, `ss.shellFlag`, `ss.lastSize`, `ss.ptmx`, `ss.cmd`, `ss.stopCh = make(chan struct{})`, `ss.running = true`.
    - Snapshot `stopCh := ss.stopCh`.
    - `ss.readerWg.Add(1)` then `go ss.readLoop(ptmx, stopCh)`.
    - `go ss.monitorExit(cmd, ptmx, stopCh)`.
    - Return nil.

    **2. `(ss *sessionState) stopSessionLocked()`:**
    - Receiver is `*sessionState`. `ss.mu` MUST be held.
    - If `ss.stopCh != nil`, close it, set to nil.

    **3. `(ss *sessionState) readLoop(ptmx *os.File, stopCh chan struct{})`:**

    - `startEmitter`: Create `ss.outputCh = make(chan string, 512)`, `ss.emitterWg.Add(1)`, goroutine with 8ms ticker + 32KB flush threshold.
    - `flush()` inside goroutine: if buf empty, return. Increment `ss.outputSeq` atomically. Emit via `wailsApp.Event.Emit("pty-output:"+ss.id, ...)` per D-04 namespaced format. Reset buf.
    - `stopEmitter`: Close `ss.outputCh`, wait `ss.emitterWg`, nil out outputCh.

    **5. `(ss *sessionState) enqueueOutput(data string)`:**
    - Same as old `enqueueOutput`: non-blocking send to `ss.outputCh`, log every 100th drop.

    **6. Update `CreateSession` (from Plan 01) to call PTY start:**
    - After creating `ss` and before returning, add:
      - Call `startEmitter()` on ss to initialize output channel + emitter goroutine.

      - If startSessionLocked fails, return error per D-07.
    - Remove the old Plan 01 note about "not calling startSessionLocked yet."

    **7. Implement sessionId-parameter dispatch methods:**

    **`Write(sessionId string, data string) error`:**
    - Call `s.resolveSession(sessionId)` to get `ss`.
    - Lock `ss.mu`, defer unlock.
    - If `!ss.running`, call `s.startSessionLocked(ss, int(ss.lastSize.Cols), int(ss.lastSize.Rows))` — per D-07, Write auto-resumes stopped shell.
    - If `ss.ptmx == nil`, return error "terminal not started".
    - Write data bytes to `ss.ptmx` in a loop handling partial writes.
    - Return nil.

    **`Resize(sessionId string, cols, rows int) error`:**
    - Call `s.resolveSession(sessionId)` to get `ss`.
    - Lock `ss.mu`, defer unlock.
    - Validate: cols/rows in range 1..65535. Return error if invalid.
    - If `ss.ptmx == nil`, return error "terminal not started".
    - Update `ss.lastSize`. Call `ptyResize(ss.ptmx, cols, rows)`. Return error from ptyResize.

    **`Clear(sessionId string) error`:**
    - Dispatch to `Write(sessionId, "\x1b[H\x1b[2J\x1b[3J")`. Also emit namespaced clear event:
    - After Write succeeds, emit: `wailsApp.Event.Emit("pty-cleared:"+sessionId, nil)`.
    - Return Write's error.

    **`Start(sessionId string, cols, rows int) error`:**
    - Call `s.resolveSession(sessionId)` to get `ss`.
    - Lock `ss.mu`, defer unlock.
    - Call `s.startSessionLocked(ss, cols, rows)`. Return error.

    **`Stop(sessionId string) error`:**
    - Call `s.resolveSession(sessionId)` to get `ss`.
    - Lock `ss.mu`. Set `ss.intentionalStop = true`. Call `ss.stopSessionLocked()`.
    - Snapshot `oldPtmx := ss.ptmx; oldCmd := ss.cmd`. Clear `ss.ptmx = nil; ss.cmd = nil; ss.running = false`.
    - Unlock `ss.mu`. Close oldPtmx. Kill oldCmd process group. Wait `ss.readerWg`. Return nil.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PTY process ↔ Go backend | Shell process output crosses into Go via PTY fd; Go sends keystrokes to shell via PTY fd |
| Go backend → Frontend (Wails events) | PTY output data and exit codes cross from Go to frontend via namespaced events |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02 | Denial of Service | ServiceShutdown / CloseSession | mitigate | `CloseSession` kills PTY process group (SIGHUP→SIGKILL escalation via `killProcessGroup`), waits `readerWg`, stops emitter, waits `emitterWg`. `ServiceShutdown` snapshots all IDs under lock, closes each without holding lock. No zombie processes or leaked goroutines. |
| T-21-03 | Denial of Service | Goroutine leak on rapid create/close | mitigate | `startSessionLocked` tracks goroutines via `ss.readerWg` and `ss.emitterWg`. `CloseSession` waits on both before returning. |
| T-21-04 | Denial of Service | Deadlock from mutex held across blocking ops | mitigate | `startSessionLocked` unlocks `ss.mu` before PTY close and `readerWg.Wait()`, re-locks after (preserved from old `startLocked` pattern). `CloseSession` releases `s.mu` before PTY close and goroutine waits. `ServiceShutdown` snapshots IDs under lock, iterates without lock. |
| T-21-05 | Information Disclosure | Session A output appearing in session B | mitigate | Each `sessionState` has its own `outputCh`, `ptmx`, and emitter goroutine. Emitter uses `"pty-output:"+ss.id` namespaced event. No shared buffers or channels between sessions. |
| T-21-06 | Tampering | Shell injection via PTY Write | accept | PTY input is user-controlled by design (interactive terminal emulator). Keystroke data is forwarded verbatim — this is expected behavior. Terminal emulator cannot be sandboxed; the shell runs with user's full permissions. |
</threat_model>
