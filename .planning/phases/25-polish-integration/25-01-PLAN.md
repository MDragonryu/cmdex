<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → TerminalService | The frontend calls `CreateSession`, `CloseSession`, `Write`, `Resize`, etc. via Wails bindings. The ptyBackend refactor does not move or widen this boundary. |
| TerminalService → OS PTY | The new `ptyBackend` interface is the seam between `terminal_service.go` and the OS layer (creack/pty on darwin, conpty on windows). It is an internal Go interface, not a network or IPC boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01-01 | Tampering | `ptyBackend` interface | accept | The interface is internal package state. No external input crosses it. The mock is `//go:build darwin` and is never compiled into the production darwin binary, so no mock code can run in production. |
| T-25-01-02 | Elevation of Privilege | `mockPtyBackend` (test only) | mitigate | The mock is build-tagged `//go:build darwin` AND placed in a `_test.go` helper file; it cannot be reached from any non-test code path. The mock's `Kill` only operates on the `*exec.Cmd` returned from its own `Start` (a `sleep 0.05` process) — no real user shell is ever passed to the mock. |
| T-25-01-SC | Tampering | Go module dependencies | mitigate | This plan adds no new Go module dependencies. The existing `github.com/creack/pty v1.1.24` is the only PTY library and is already in `go.mod`. `github.com/wailsapp/wails/v3` is already used. No new direct require. |
</threat_model>
