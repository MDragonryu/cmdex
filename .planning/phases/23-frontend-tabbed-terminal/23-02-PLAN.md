        // For each session, listen to its pty-exit event
        const subscribeSession = (sessionId: string) => {

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Tampering (Input Validation) | renameTerminalSession callback in App.tsx | mitigate | Session rename validates name.trim() is non-empty before calling RenameSession. Empty/whitespace-only names are silently rejected. Per ASVS V5.1.4. |
| T-23-02 | Denial of Service (Resource) | Events.On subscriptions in useEffect | mitigate | All Events.On subscriptions (pty-exit per session, pty-cleared per session) are cleaned up in useEffect return functions. Event listener count does not grow unbounded as sessions are created/destroyed. |
| T-23-03 | Denial of Service (Resource) | xterm.js instances per session | accept | Each TerminalComponent creates an xterm.js instance (~5-10MB each). With no session limit, a user could create many sessions and exhaust renderer memory. Accepted — this is a local desktop app; the user is the only actor. Future phases could add a session limit (e.g., 20 max). |
| T-23-04 | Information Disclosure | Terminal output in hidden instances | accept | Hidden TerminalComponent instances retain their xterm.js buffer in memory. If a future feature enumerates terminal content across sessions, this could be a concern. Currently, only the active session's output is accessible via clear/copy buttons. Accepted as low risk. |

**Assessment:** Low risk. Primary mitigations are input validation on rename and event listener cleanup. Memory concerns from multiple xterm.js instances are accepted — the user controls session count in a local app.
