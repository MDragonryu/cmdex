### Gap 1: cd sandwich trailing newline split

Root cause: `GenerateScript()` in `script.go:18` appends `"\n"` to every stored script body. When `RunCommand` reads `ScriptContent` from DB and passes it through `ReplaceTemplateVars`, the result still carries that trailing `\n`. Embedding `resolvedScript` into the cd sandwich at `execution_service.go:128` produces two lines of shell input — the PTY interprets the first `\n` as line terminator, sending ` && cd ~` as a separate invalid command.

### Gap 2: keystroke lag + dropped bytes

Two root causes: (a) 50ms idle timeout in `Terminal.tsx:159` defers ALL keystroke sends — user gets zero echo feedback during fast typing until they pause. (b) `TerminalService.Write` at `terminal_service.go:216` discards the byte count (`_, err := s.ptmx.Write(...)`), silently losing bytes on any short write from the PTY.

### Gap 3: clear button invisible + blank after clear

Two root causes: (a) CSS `opacity: 0` on `.terminal-clear-btn` at `style.css:1995` — button only visible on hover (copied from collapse button pattern, but clear is not a toggle). (b) `Terminal.clear()` at `Terminal.tsx:28` programmatically wipes the xterm.js buffer, then `Write('clear\r')` arrives through normal PTY emulation — but xterm.js fails to repaint until the next keystroke triggers a render cycle. The fix replaces `term.clear()` with `Write('\x0c')` (Ctrl+L form-feed), keeping everything in the PTY emulation pipeline.

**Gap 2 — Keystroke lag + dropped bytes. Fix terminal_service.go Write and Terminal.tsx keystroke buffer.**

**terminal_service.go (line 216):** Replace the single `s.ptmx.Write([]byte(data))` with a full-write loop. A PTY `Write` may return a short write under burst conditions — discarding `n` with `_` silently loses tail bytes. Replace lines 216-217:

```go
_, err := s.ptmx.Write([]byte(data))
return err
```

with a loop that retries until all bytes are written:

```go
b := []byte(data)
for len(b) > 0 {
    n, err := s.ptmx.Write(b)
    if err != nil {
        return err
    }
    b = b[n:]
}
return nil
```

This guarantees every byte reaches the PTY regardless of write buffer limits. The `s.mu` lock already protects against concurrent writes, so no additional synchronization needed.

**Terminal.tsx (lines 136-169 — keystroke buffer useEffect):** Two changes:

1. **Remove 50ms idle timeout (line 159).** Replace the idle timer with immediate flush on every keystroke. The 50ms batch defers ALL echo feedback until the user pauses — there is no Wails overhead justification for delaying keystroke echo in a local app. New handleData:
   - Accumulate keystrokes in buffer as before
   - If `data.includes('\r')`: flush immediately (Enter key pressed — could be single `'\r'` or part of a multi-char payload like paste)
   - Otherwise: flush immediately — no idle timer
   - Remove `flushTimer` variable and all `setTimeout`/`clearTimeout` logic

2. **Change Enter detection from strict `data === '\r'` to `data.includes('\r')` (line 153).** xterm.js may batch characters including `\r` in edge cases (fast paste, backlog processing). `includes` is safe because `\r` is not a valid character in shell command text — it only appears as Enter.

The resulting `handleData`:
```typescript
const handleData = (data: string) => {
    keystrokeBuffer += data;
    flushBuffer();
};
```

This simplifies away the conditional altogether — every call to `handleData` flushes immediately. The `flushBuffer` function (lines 139-149) stays unchanged — it batches what's in the buffer into a single `Write` call, which is efficient enough.

The cleanup in the returned function (lines 166-169) still calls `flushBuffer()` to drain any remaining keystrokes on unmount. Remove the `clearTimeout(flushTimer)` line since there is no timer.

**Gap 3 — Clear button invisible + blank after clear.**

**Terminal.tsx (lines 26-31 — useImperativeHandle clear method):** Replace the two-step clear that causes buffer/PTY desync. Current code:
```typescript
clear: () => {
```

Replace with single PTY-path clear that keeps everything in the emulation pipeline:

`\x0c` is the ASCII Form Feed character (Ctrl+L) — the universal terminal clear-screen command. When sent through the PTY, the shell processes it in the normal emulation stream, clears the screen, and repaints the prompt at the top. No buffer/rendering desync because xterm.js's emulation layer handles it natively.

Remove the `terminalRef` no longer needed by `clear()` — but keep the ref for potential future use (it's used by `term.onData` and `term.write` in other effects). The `TerminalHandle` interface and `useImperativeHandle` wrapper stay — only the implementation of `clear()` changes.
