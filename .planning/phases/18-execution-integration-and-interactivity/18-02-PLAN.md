      ```tsx
      useEffect(() => {
          const term = terminalRef.current;
          if (!term) return;

          let keystrokeBuffer = '';
          let flushTimer: ReturnType<typeof setTimeout> | null = null;

          const flushBuffer = () => {
              if (keystrokeBuffer.length > 0) {
                  const batch = keystrokeBuffer;
                  keystrokeBuffer = '';
                  Write(batch).catch((err) => console.error('TerminalService.Write failed:', err));
              }
              if (flushTimer) {
                  clearTimeout(flushTimer);
                  flushTimer = null;
              }
          };

          const handleData = (data: string) => {
              keystrokeBuffer += data;
              if (data === '\r') {
                  // Enter key — flush immediately
                  flushBuffer();
              } else {
                  // Reset idle timer: flush after 50ms of inactivity per D-02
                  if (flushTimer) clearTimeout(flushTimer);
                  flushTimer = setTimeout(flushBuffer, 50);
              }
          };

          term.onData(handleData);

          return () => {
              // Cleanup: flush any remaining keystrokes and clear timer
              if (flushTimer) clearTimeout(flushTimer);
              flushBuffer();
              // Note: term.onData has no built-in unsubscribe;
              // the Terminal instance is disposed in the init useEffect cleanup
          };
      }, []);
      ```

    **Key design decisions (per D-02, D-03, and Agent Discretion):**
    - Buffer accumulation: string concatenation in `keystrokeBuffer`
    - Flush trigger: `\r` (Enter) flushes immediately; otherwise 50ms idle timeout
    - Ctrl+C: `\x03` byte captured by `term.onData` and forwarded through same buffer path — PTY driver translates to SIGINT. No separate Interrupt() method needed (D-03).
    - Clear: `term.clear()` clears xterm.js scrollback AND `Write('clear\r')` clears shell screen (both approaches per Agent Discretion)
    - Buffer flushed on unmount/cleanup to prevent data loss per Pitfall 3
    - Write errors logged to console (not user-visible — PTY connectivity errors would be visible in terminal anyway)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User keyboard → term.onData | Raw keystrokes captured by xterm.js textarea handler; any byte sequence can be sent |
| Client-side buffer → TerminalService.Write | Batched keystrokes sent to Go via Wails IPC; contains user-typed text including control chars |
| TerminalService.Write → PTY stdin | Bytes written directly to shell process; shell interprets them as stdin input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-06 | Tampering | Terminals.tsx keystroke buffer | accept | User controls the terminal — intentional input is the feature. The PTY shell is the user's own process running as the same OS user. No privilege boundary crossed. Malicious input (e.g., `rm -rf /`) is user self-harm, not a security threat. |
| T-18-07 | Spoofing | TerminalService.Write Wails binding | accept | Wails IPC is internal to the desktop app process. No external network surface. Binding ID is compiler-generated. No authentication bypass risk. |
| T-18-08 | Information Disclosure | term.onData buffer held in memory | accept | Buffer holds keystrokes in JS string in browser memory for max 50ms. No persistence, no disk storage. Flushed to PTY (user's own shell) or discarded on unmount. |
| T-18-09 | Elevation of Privilege | terminalRef.clear() calling Write('clear\r') | accept | `clear\r` is a benign shell builtin. No privilege escalation. Write goes through same TerminalService.Write path as keystrokes — same user, same shell, same process. |
| T-18-10 | Denial of Service | 50ms idle timer flood | mitigate | Each keystroke resets the idle timer, creating at most one `Write` call per 50ms idle period. `\r` (Enter) flushes immediately. Maximum call rate is naturally bounded by human typing speed + Enter presses. No amplification vector. |
| T-18-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase. All dependencies already present and verified in prior phases. |
</threat_model>
