    **Add inside the useEffect body (after the ptyExit subscription, before the return statement):**

    ```ts
    // Subscribe to cmd-output events from RunCommand (ExecutionService)
    const cleanupCmd = Events.On(eventNames.cmdOutput, (event: { data: { stream: string; data: string } }) => {
      const chunk = event?.data;
      if (!chunk?.data) return;
      if (chunk.stream === 'stderr') {
        // Write stderr in ANSI red to distinguish from stdout
        term.write('\x1b[31m' + chunk.data + '\x1b[0m');
      } else {
        term.write(chunk.data);
      }
    });
    ```

    **Update the return statement to call `cleanupCmd()` as well:**

    The existing return is:
    ```ts
    return () => {
      cleanupOutput();
      cleanupExit();
    };
    ```

    Change to:
    ```ts
    return () => {
      cleanupOutput();
      cleanupExit();
      cleanupCmd();
    };
    ```

    **Why this works:**
    - `cmd-output` events fire from `execution_service.go RunCommand` (line 109: `wailsApp.Event.Emit(eventNames.CmdOutput, chunk)`) during script execution.
    - Unlike `pty-output` which uses Go's `map[string]interface{}{"data": data}` (double-unwrapped), `cmd-output` emits `OutputChunk{Stream, Data}` directly — single unwrap: `event.data.stream` / `event.data.data`.
    - The subscription is persistent (empty deps array) — catches ALL execution runs regardless of active tab.
    - Stdout written raw; stderr wrapped in ANSI red (`\x1b[31m...\x1b[0m`) for visual distinction.
    - No changes to `events.ts` or Wails bindings needed — `eventNames.cmdOutput` already exists.
