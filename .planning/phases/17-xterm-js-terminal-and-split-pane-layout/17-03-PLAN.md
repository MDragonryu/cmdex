    **B. Add a second useEffect for event subscriptions (after the terminal lifecycle useEffect, before the return statement):**
    This is a separate useEffect because it depends on `terminalRef.current` being set (which happens in the first useEffect), and the subscriptions are stable (empty dependency array).

    ```
    useEffect(() => {
      const term = terminalRef.current;
      if (!term) return;

      // Subscribe to PTY output events from TerminalService
      const cleanupOutput = Events.On(eventNames.ptyOutput, (event: { data: { data: string } }) => {
        // Wails v3 wraps Go-emitted events in { name, data, sender }
        // The Go backend emits: { data: "raw PTY bytes" }
        // So the payload is at event.data.data (double unwrap)
        const output = event?.data?.data;
        if (output) {
          term.write(output);
        }
      });

      // Subscribe to shell exit events from TerminalService
      const cleanupExit = Events.On(eventNames.ptyExit, (event: { data: { exitCode: number; wasIntentional: boolean } }) => {
        const { exitCode, wasIntentional } = event?.data ?? {};
        // The Go backend (terminal_service.go line 141) writes "[shell exited..."
        // to PTY output before emitting the pty-exit event, so the exit message
        // already appears in the terminal. No additional frontend action needed.
        console.log(`Shell exited: code=${exitCode}, intentional=${wasIntentional}`);
      });

      return () => {
        cleanupOutput();
        cleanupExit();
      };
    }, []);
    ```

    **C. Ensure no subscription in first useEffect:**
    - The existing terminal lifecycle useEffect (deps: `[monoFont]`) should NOT contain Events.On calls — subscriptions go in this new, separate useEffect

    - Both cleanup functions are called in the useEffect return
    - This prevents event listener accumulation on hot reload (Pitfall 4)
    - Empty dependency array ensures subscriptions are set up once and cleaned up once

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go PTY → Wails event bridge → React | Untrusted PTY output crosses from backend process to frontend DOM |
| TerminalService Go method calls → npm bindings | Wails binding generation produces TypeScript wrappers for Go service methods |
| events.ts hardcoded fallback → Go backend override | Event name strings can be overridden by backend EventNames |
| npm package registry → `wails3 generate build-assets` | Generated bindings come from Wails CLI tool |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-09 | Tampering | pty-output event payload | mitigate | xterm.js renders PTY output as display-only text — no code execution. ANSI escape sequences are parsed by xterm.js's safe VT parser, not by shell or eval(). Backend emits raw bytes; frontend writes to terminal via `term.write()` which sanitizes DOM output. |
| T-17-10 | Information Disclosure | Clipboard injection via OSC 52 | mitigate | xterm.js v6 disables OSC 52 (clipboard) by default. `allowProposedApi: true` enables addon support but does not enable OSC 52. WebLinksAddon only responds to explicit user clicks on detected URLs. |
| T-17-11 | Elevation of Privilege | Wails binding regeneration | accept | `wails3 generate build-assets` is a build-time operation run locally. Generated bindings are type-safe wrappers over Go service methods. No runtime privilege escalation — bindings only expose methods already registered in main.go Services slice. |
| T-17-12 | Denial of Service | Event listener accumulation | mitigate | useEffect cleanup returns `cleanupOutput()` and `cleanupExit()` callbacks. Empty dependency array ensures one subscription per component lifecycle. StrictMode double-mount is handled by the ref guard in the terminal lifecycle useEffect (17-01). |
| T-17-13 | Information Disclosure | Event name fallback mismatch | mitigate | events.ts provides hardcoded fallback strings matching Go backend's `eventNames.PtyOutput = "pty-output"` and `eventNames.PtyExit = "pty-exit"` (verified in event_service.go). initEventNames() attempts to override with backend values — if that fails, hardcoded fallbacks still work. |
</threat_model>
