### Test Structure and Design

**IMPORTANT:** PTY tests spawn real processes. Use short-circuit guards:
- Use `testing.Short()` to skip full integration tests in CI: `if testing.Short() { t.Skip("skipping integration test in short mode") }`
- Tests that don't need a real PTY (batching logic, shell detection) run in all modes
- Tests that spawn a real shell (Start, Write, Resize, Shutdown, Exit) are gated behind `-run Integration` or `!testing.Short()`

Use `/bin/echo` or `/bin/cat` instead of an interactive shell (bash/zsh) for integration tests to make them deterministic and fast. An interactive shell waits for input indefinitely — use non-interactive commands wrapped in the detected shell. The actual shell binary is detected by `detectShell()` but the test spawns it with a specific command.

For example, to test Write:
```go
// Spawn shell with a command that echoes back
cmd := exec.Command(shellPath, "-c", "cat")
ptmx, _ := pty.StartWithSize(cmd, &pty.Winsize{Rows: 24, Cols: 80})
ptmx.Write([]byte("hello\n"))
// Read output from ptmx, verify "hello" appears
```

### Design Notes: *os.File vs io.ReadWriteCloser tradeoff

The planner explored four approaches for the type mismatch between `TerminalService.ptmx` (*os.File) and go-winpty's return types:

| Option | Description | Verdict |
|--------|-------------|---------|
| A | Change ptmx to `io.ReadWriteCloser` in terminal_service.go + update terminal_unix.go | Cleanest but modifies files from Plan 16-01 + conflicts with 16-02 (same wave) |
| B | Create synthetic *os.File via os.Pipe() proxy | Fragile, complex, error-prone for bidirectional I/O |
| C | Use os.NewFile() with winpty file descriptor | Requires go-winpty to expose fd (unlikely for Windows handles) |
| D | Platform-specific interface wrapper in terminal_service.go | Overengineering for two implementations |

**Resolution:** Discovery-first approach (STEP 2 above). `go-winpty` is marked [ASSUMED] in RESEARCH.md — its API surface is uncertain. The executor inspects the actual API and branches. Option A (io.ReadWriteCloser) can be executed in this task if go-winpty doesn't provide *os.File — the file conflict with Plan 16-02 is acceptable since both are Wave 2 and 16-03 modifies terminal_service.go only for the field type change (a 1-line diff).
