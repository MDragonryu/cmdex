### Test Structure and Design

**IMPORTANT:** PTY tests spawn real processes. Use short-circuit guards:
- Use `testing.Short()` to skip full integration tests in CI: `if testing.Short() { t.Skip("skipping integration test in short mode") }`
- Tests that don't need a real PTY (batching logic, shell detection) run in all modes
- Tests that spawn a real shell (Start, Write, Resize, Shutdown, Exit) are gated behind `-run Integration` or `!testing.Short()`

Use `/bin/echo` or `/bin/cat` instead of an interactive shell (bash/zsh) for integration tests to make them deterministic and fast. An interactive shell waits for input indefinitely — use non-interactive commands wrapped in the detected shell. The actual shell binary is detected by `detectShell()` but the test spawns it with a specific command.

For example, to test Write:
```go
// Spawn shell with a command that echoes back
cmd := exec.Command(shellPath, "-c", "cat")
ptmx, _ := pty.StartWithSize(cmd, &pty.Winsize{Rows: 24, Cols: 80})
ptmx.Write([]byte("hello\n"))
// Read output from ptmx, verify "hello" appears
```
