### STEP 2: Add `readLoop` method

Add to TerminalService an unexported goroutine function:

```go
func (s *TerminalService) readLoop() {
    reader := bufio.NewReaderSize(s.ptmx, 64*1024)
    ticker := time.NewTicker(16 * time.Millisecond)
    defer ticker.Stop()

    var buf bytes.Buffer
    buf.Grow(64 * 1024)

    for {
        select {
        case <-s.stopCh:
            // Drain remaining buffered output before exiting
            if buf.Len() > 0 {
                s.emitOutput(buf.String())
            }
            return
        case <-ticker.C:
            if buf.Len() > 0 {
                s.emitOutput(buf.String())
                buf.Reset()
            }
        default:
            chunk := make([]byte, 4096)
            n, err := reader.Read(chunk)
            if n > 0 {
                buf.Write(chunk[:n])
                if buf.Len() >= 64*1024 {
                    s.emitOutput(buf.String())
                    buf.Reset()
                }
            }
            if err != nil {
                // PTY closed or read error — shell likely exited
                // Drain remaining buffer before returning
                if buf.Len() > 0 {
                    s.emitOutput(buf.String())
                }
                return
            }
        }
    }
}
```

Key design decisions (the agent's discretion from CONTEXT.md):
- **Ticker:** `time.NewTicker(16 * time.Millisecond)` — 16ms interval per PTY-03
- **Buffer:** `bufio.NewReaderSize(s.ptmx, 64*1024)` — 64KB read buffer, matches PTY-03 max chunk
- **Accumulation buffer:** `bytes.Buffer` with `Grow(64*1024)` pre-allocation — collects reads between ticks
- **Immediate emit:** When buffer reaches 64KB, emit immediately without waiting for ticker
- **Drain on exit:** When stopCh fires OR reader error, drain remaining buffer before returning
- **Non-blocking read:** `default` case in select allows ticker to fire even when no PTY data is available
- **4KB read chunks:** `make([]byte, 4096)` — small enough to not block, large enough to be efficient

New imports needed: `"bufio"`, `"bytes"`, `"time"` — add to the import block in terminal_service.go.

### STEP 1: Add `monitorExit` method

Add to TerminalService:

```go
func (s *TerminalService) monitorExit() {
    err := s.cmd.Wait()

    exitCode := 0
    wasIntentional := false

    if err != nil {
        if exitErr, ok := err.(*exec.ExitError); ok {
            exitCode = exitErr.ExitCode()
        } else {
            exitCode = -1
        }
    }

    // Exit code 0 = intentional (user typed "exit" or Ctrl+D)
    if exitCode == 0 {
        wasIntentional = true
    }

    // Emit pty-exit event (D-05)
    wailsApp.Event.Emit(eventNames.PtyExit, map[string]interface{}{
        "exitCode":      exitCode,
        "wasIntentional": wasIntentional,
    })

    // Write restart message to terminal output BEFORE restarting (D-04)
    // Use emitOutput so it appears in the terminal stream
    restartMsg := fmt.Sprintf("\r\n[shell exited with code %d — restarting...]\r\n", exitCode)
    s.emitOutput(restartMsg)

    // Auto-restart after brief delay (D-03)
    time.Sleep(100 * time.Millisecond)

    // Re-spawn the shell with the last known terminal size
    _ = s.Start(int(s.lastSize.Cols), int(s.lastSize.Rows))
}
```

Key design details:
- **Exit code 0 = intentional:** Per RESEARCH.md Pattern 5 — if the user types `exit` or sends Ctrl+D, the shell exits with code 0. Non-zero exit codes indicate crashes or `exit 1`-style termination.
- **Restart message:** Uses `\r\n` prefix/suffix to ensure it appears on a new line in the terminal output. The `\r\n` before the message ensures it starts on a fresh line (terminal output may not have ended with a newline).
- **100ms restart delay:** Brief delay to avoid tight restart loops if the shell crashes immediately on every spawn. Per the agent's discretion.
- **Re-spawn with lastSize:** Uses `s.lastSize` stored by Start/Resize (Pitfall 5 from RESEARCH.md — prevents default 80×24 on restart).
- **Event emitted BEFORE restart:** The `pty-exit` event fires before re-spawning so the frontend can show a transient "disconnected" state if needed (Phase 17).

### STEP 3: Ensure Stop() handles monitorExit gracefully

The existing `Stop()` method already closes `s.stopCh` which signals readLoop. The `monitorExit` goroutine is not watching stopCh — it's blocked on `s.cmd.Wait()`. When Stop() calls the platform kill function (killProcessGroupUnix), the shell process is killed, `cmd.Wait()` returns, and monitorExit proceeds to emit the exit event and attempt auto-restart.

**CRITICAL:** There's a race condition here. If Stop() kills the shell, monitorExit unblocks and calls `s.Start(...)` to auto-restart — but we're in the middle of stopping. To prevent this, add a check at the start of `monitorExit`:

After `err := s.cmd.Wait()`, check if we're shutting down:
```go
select {
case <-s.stopCh:
    return // Don't auto-restart if shutting down
default:
    // Continue with exit event and auto-restart
}
```

Add this check BEFORE emitting the pty-exit event and restart message. When the app is shutting down (stopCh closed), monitorExit silently returns without restarting. During normal operation (user typed `exit`), stopCh is open, so auto-restart proceeds.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PTY reader goroutine → Wails event bridge | PTY output data crosses from Go to frontend via event emission |
| Shell exit monitor → Wails event bridge | Exit notification crosses Go→frontend boundary |
| Shell exit monitor → PTY output stream | Restart message written to emitOutput before re-spawn |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-05 | Denial of Service | readLoop — Wails event bridge saturation | mitigate | 16ms ticker + 64KB max buffer enforces max ~62 events/sec regardless of PTY output rate. Without batching, `cat largefile.txt` would flood 10,000+ events across the bridge. |
| T-16-06 | Denial of Service | monitorExit — tight restart loop | mitigate | 100ms delay between exit detection and re-spawn prevents CPU spin if shell crashes immediately. Max restart rate: ~10/sec. |
| T-16-07 | Elevation of Privilege | monitorExit — stopCh race during shutdown | mitigate | monitorExit checks `s.stopCh` before auto-restart; if stopCh is closed (app shutting down), exit silently without re-spawning. Prevents shell from restarting during app termination. |
| T-16-08 | Information Disclosure | emitOutput — ANSI escape sequences in PTY output | accept | PTY output includes ANSI escape sequences (colors, cursor movement). These pass through verbatim in pty-output events. xterm.js (Phase 17) renders them safely. No sensitive data in PTY output (not persisted). |
</threat_model>
